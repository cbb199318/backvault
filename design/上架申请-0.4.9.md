## 提交前要先确认的三件事

### 1. run-as root（表单第 1 条：root 权限应用无法上架，会被自动忽略）

`encbackup/config/privilege` 现在是 `"run-as": "root"`。0.4.4 当时能上架，但这条规则写在表单最前面，
这次很可能会被直接忽略。改成以应用自己的用户（`encbackup`）运行需要：

- 确认 restic 能读到用户授权的目录（飞牛通过「应用授权目录」给应用用户授权）
- 应用数据目录 `/vol1/@appdata/encbackup` 的属主
- 在线更新替换自身二进制的写权限

改动不小，需要单独做一轮并在真机上验证，再提交。

### 2. 应用内在线更新

应用会绕过应用中心，从 GitHub 下载新版本替换自身。表单没有明说禁止，但审核可能会问。
备注里已如实写明（签名校验、回滚）。如果官方不接受，可以给商店版加一个开关，默认关闭在线更新。

### 3. ARM 包未上机验证

ARM 包是交叉编译的（`encbackup-server`、restic、rclone 都已确认是 ARM aarch64），
但没有在真实 ARM 机型上装过。表单第 3 条要求「提交前自己验证可安装可运行」。
如果没有 ARM 设备，平台可以先只选 x86、只传 x86 包。

## 重新打 ARM 包

```bash
FNPACK="$(cd ../tools && pwd)/fnpack"
S=/tmp/fpk-arm && rm -rf $S && mkdir -p $S
(cd backend && GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build -ldflags="-s -w -X main.appVersion=0.4.9" -o $S/encbackup-server-arm64 .)
cp -R encbackup $S/encbackup
cp $S/encbackup-server-arm64 $S/encbackup/app/server/encbackup-server
cp /tmp/encbin-arm/restic /tmp/encbin-arm/rclone $S/encbackup/app/server/engines/
sed -i '' 's/^platform=x86/platform=arm/' $S/encbackup/manifest
(cd $S && "$FNPACK" build --directory encbackup)   # 先 ./build.sh 生成前端与 public 目录
```
