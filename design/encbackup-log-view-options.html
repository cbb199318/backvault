「查看日志」优化方案预览

现状问题：日志抽屉直接显示 restic 原始输出 —— 命令回显 + [diag] + 数百条 JSON status 轮询 + 末尾 summary JSON，普通用户看不懂。

原始日志长这样（片段）：
{"message_type":"status","seconds_elapsed":5,"percent_done":0.5322616075324769,"total_files":621,"files_done":274,...}
{"message_type":"status","seconds_elapsed":5,"percent_done":0.562997948259582,"total_files":631,...} ……重复上百条
方案 1结果摘要卡（首屏只看结论）

打开日志先给一张「结果摘要卡」：状态 / 文件数 / 数据量 / 用时四个大字，下面是关键时间轴（开始 → 扫描 → 上传 → 完成），错误用黄色标出可点开。原始日志折叠到底部，默认不展开。

方案 2实时进度面板（运行中看动效）

运行中显示一个大进度条 + 实时跳动的「已上传 / 速度」，底下滚一条当前正在处理的文件名；结束后自动切换成方案 1 的摘要卡。适合「备份时点进来看看跑到哪了」。

方案 3分层折叠（进阶用户可下钻）

三级结构：摘要 → 关键事件 → 原始 JSON（默认折叠）。顶部用标签切换「摘要 / 事件 / 原始」。兼顾小白（只看摘要）和排查问题的进阶用户（可展开原始）。

方案 4「一句话」结果 + 图形化

最激进：把日志抽象成一句人话（"今早 3 点备份成功，上传 1.2 万文件 / 13.5GB，用时 18 分钟"），配一条迷你进度/耗时条形图。日志几乎不露 JSON，只留一个「下载日志」按钮。

建议：方案 1（结果摘要卡）最均衡，覆盖大多数「我就想知道这次成功没、传了多少」的诉求；方案 2 补上「运行中实时看」的体验。两者可组合：运行中 → 方案 2 实时面板，结束后 → 方案 1 摘要卡。原始日志统一折叠成「查看原始日志」入口，进阶排查才展开。后端只需解析 restic 的 status/summary/error JSON 行即可，无需改 restic 本身。
