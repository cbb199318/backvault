快照 Tab · 合并「还原 + 仓库」

底部导航从三项（备份 / 还原 / 仓库）收敛为两项（备份 / 快照）。快照 tab 内一条路径走到底：仓库列表 → 展开快照 → 快照详情 → 还原。

需求拆解

  1. 「还原」和「仓库」合并为一个 tab，名字叫快照
  2. 快照 tab 首屏是仓库列表
  3. 点仓库展开，显示该仓库下的快照列表
  4. 点快照显示快照详情
  5. 详情里有还原按钮，点它进入还原
顺带解决一个问题：现在还原向导是 5 步（选任务 → 选快照 → 选文件 → 目的地 → 冲突）。合并后「选任务」「选快照」被浏览行为替代了 —— 你已经在某个快照的详情页里，点还原就直接从「选文件」开始。5 步变 3 步，少点两次。
三方案对比
都满足需求，差别在「浏览时信息密度」和「点几次能到还原」。

方案 A · 手风琴内联 推荐
仓库是卡片，点整张卡片展开，快照表直接内联在卡片里往下长。点快照行，整个 tab 内容切成详情页，顶部面包屑可以退回。详情页右上角「还原此快照」是主按钮。
下面这块可以点：先点仓库卡展开，再点任意快照行进详情，再点「还原此快照」。
1 仓库列表→ 2 展开快照→ 3 快照详情→ 4 还原配置→ 5 执行完成

实现要点
三套方案的数据接口完全一样，只是布局不同。选定方案后，改动集中在导航和视图层。

导航改造

  • 底部/侧边导航从 3 项减到 2 项：备份、快照
  • nav 取值改为 tasks / snap
  • 删掉独立的「还原」入口，FAB 在快照页隐藏
  • 快照页内部用 snapView 管理层级：list / detail / restore

数据接口（已有，直接复用）

  • GET /api/repos/summary — 仓库列表 + 快照数 + 最近时间，只读缓存
  • GET /api/repos/:id/snapshots — 某仓库下快照，含任务归属
  • GET /api/tasks/:id/snapdiff — 与上一快照差异
  • POST /api/tasks/:id/restore — 执行还原

还原向导简化

  • 原来 5 步：选任务 → 选快照 → 选文件 → 目的地 → 冲突
  • 合并后 3 步：选文件 → 目的地 → 冲突
  • rst.task 和 rst.cur 从快照详情页直接注入
  • 进入时跳过 rstStep 0/1，直接从 rstStep=2 开始

要留意的坑

  • 快照 summary 为空时（旧快照），文件数/大小显示 — 而不是 0
  • tag 不是 task:xxx 的快照归到「未关联任务」组，别硬塞给某个任务
  • 仓库展开状态要记忆，避免切 tab 回来全部收起
  • 手机端详情页的还原按钮固定在底部，别被导航栏盖住
我的建议：选方案 A。它在桌面和手机上是同一套布局，改动量最小（现在的仓库页稍作改造就能用），而且手风琴展开这个交互和你已经熟悉的备份 tab 卡片风格是一致的。方案 B 的桌面体验确实更好，但要额外维护一套手机端布局，性价比不高。如果你主要在电脑上用，那 B 更爽。
